[![Cardano](https://img.shields.io/badge/Cardano-Preprod%20%7C%20Mainnet-0033AD.svg)](https://cardano.org)

A professional, script-driven toolkit for deploying NFT collections to Cardano — a one-shot Plutus minting policy (mint exactly once, burn anytime), CIP-25 metadata, and TypeScript scripts to mint and burn. Built on [Lucid](https://github.com/spacebudz/lucid) (`lucid-cardano`) and [Aiken](https://aiken-lang.org).

## Cardano native-NFT primer

Cardano does NFTs differently from account-based chains:

- **No smart contract needed for basic NFTs.** Tokens are *native assets* — first-class citizens of the ledger, not contract state. A simple native script can mint them.
- **The minting policy IS the scarcity.** Every token is identified by `policyId + assetName`. This scaffold goes one step further than a native script: it uses a **Plutus one-shot policy**. A "seed" UTxO is baked into the script as a parameter, and the validator only succeeds when that exact UTxO is consumed. Since a UTxO can only be spent once, the policy can never mint again — the fixed supply of 1 is *provable on-chain*, not a promise.
- **Metadata lives in the transaction (CIP-25).** Token data (name, image, attributes) is attached to the mint transaction under metadata label `721`, keyed by policy ID and asset name. Wallets and marketplaces read it from there.
- **Burning is a negative mint.** The validator's `Burning` branch allows destroying the token at any time (it can only reduce supply), which is what makes corrections possible: burn the bad token, re-mint fixed art under a fresh policy.

## Features

- **One-shot Plutus policy** (Aiken) — mint exactly 1 token ever per policy; burning always allowed
- **Mint script** — derives a fresh policy per mint, attaches CIP-25 metadata, sends to any address
- **Burn script** — destroys a mis-minted token so a corrected one can be re-minted
- **CIP-25 metadata template** — `assets/metadata-template.json`, auto-filled per mint
- **Preprod-first workflow** — default network is Preprod; mainnet requires an explicit opt-in
- **CI** — GitHub Actions checks TypeScript compilation on every push (Aiken builds run locally)

## Prerequisites

- Node.js 18+
- [Aiken](https://aiken-lang.org/installation-instructions) (to compile the policy)
- A [Blockfrost](https://blockfrost.io) project ID for Preprod (later Mainnet)
- A Cardano wallet seed phrase with test ADA (faucet: https://faucet.cardano.org) — at least ~10 ADA for fees, min-UTxO, and Plutus collateral

## Quickstart

```bash
# 1. Install
npm install

# 2. Compile the one-shot policy
cd validators && aiken build && cp plutus.json .. && cd ..

# 3. Configure
cp .env.example .env
# Edit .env: set BLOCKFROST_PROJECT_ID and WALLET_SEED_PHRASE

# 4. Mint on Preprod (testnet first!)
npm run mint
# Save the printed SEED_TX_HASH / SEED_OUTPUT_INDEX into .env

# 5. (If you need to fix a mint) Burn and re-mint
npm run burn
npm run mint
```

> ⚠️ **Always test on Preprod first.** `CARDANO_NETWORK` defaults to `Preprod`. Only set it to `Mainnet` for the real launch, with a funded, dedicated deployer wallet.

```
├── .env.example

```

## Usage

### 1. Mint

```bash
npm run mint
```

Picks a pure-ADA UTxO as the one-shot seed, derives the policy, mints exactly 1 token with your CIP-25 metadata, and sends it to `MINT_RECIPIENT` (or your own address). Prints the seed reference — save it for `burn`.

### 2. Burn (corrections)

```bash
npm run burn
```

Reconstructs the policy from `SEED_TX_HASH`/`SEED_OUTPUT_INDEX`, burns the token held by your wallet, and that's it. Re-run `npm run mint` for the corrected token — it gets a fresh policy ID, which is exactly what you want buyers to verify.

## Configuration

| Variable | Description |
|---|---|
| `CARDANO_NETWORK` | `Preprod` (default) or `Mainnet` |
| `BLOCKFROST_PROJECT_ID` | Blockfrost API key for the network above |
| `BLOCKFROST_URL` | Optional RPC override |
| `WALLET_SEED_PHRASE` | BIP-39 seed of the deployer wallet |
| `PLUTUS_SCRIPT_VERSION` | `PlutusV2` (default) or `PlutusV3` — must match Aiken's output |
| `ASSET_NAME` | On-chain asset name, plain text, max 32 bytes |
| `TOKEN_DISPLAY_NAME` | Display name in CIP-25 metadata |
| `TOKEN_DESCRIPTION` | Description in CIP-25 metadata |
| `IMAGE_URI` | Artwork URI — prefer `ipfs://…` |
| `MINT_RECIPIENT` | Recipient address (defaults to deployer) |
| `SEED_TX_HASH` / `SEED_OUTPUT_INDEX` | Seed UTxO of a mint (for `burn`) |

## Security

- **Never commit `.env`** — it holds your seed phrase and Blockfrost key. Use a dedicated deployer wallet, never your main wallet.
- The seed phrase controls real funds: generate it fresh for the deployer and fund it with only what the drop needs.
- Keep a pure-ADA UTxO (≥ 5 ADA) in the deployer wallet for Plutus collateral.
- Review policy parameters on Preprod before mainnet — policy IDs are forever.
- Prefer `ipfs://` artwork URIs: HTTP URLs can be changed or taken down after the sale.

## Troubleshooting

- **`Aiken blueprint not found`** — run `cd validators && aiken build && cp plutus.json ..`.
- **Script deserialization errors** — make sure `PLUTUS_SCRIPT_VERSION` matches what Aiken emitted.
- **WASM loading errors on Node** — `lucid-cardano` ships WASM; if Node 18 refuses to load it, retry with `node --experimental-wasm-modules`.
- **Missing collateral** — keep a pure-ADA UTxO of ≥ 5 ADA in the wallet.
